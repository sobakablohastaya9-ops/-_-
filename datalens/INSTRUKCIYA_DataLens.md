# Запасной дашборд в Yandex DataLens: сборка за 60–90 минут

Зачем: если GitHub Pages не откроется у проверяющих, у нас есть вторая ссылка — дашборд в отечественном BI-инструменте на тех же данных.

Файлы лежат в папке `datalens/` (кодировка UTF-8, разделитель — запятая):

| Файл | Что внутри | Строк |
|---|---|---|
| 01_okruga.csv | паспорт 26 округов: зона, площадь, урожайность 2025, волатильность, провал 2020, влага осени 2026, вероятность убытка 2027, маржа | 26 |
| 02_urozhaj_po_godam.csv | урожайность, тренд и отклонение от тренда по годам 2008–2025 | 468 |
| 03_marzha_kraja.csv | маржа на гектар по краю по годам: урожай × цена − затраты | 10 |
| 04_ceny_mesyac.csv | цена пшеницы по месяцам и паритет «дизель / пшеница» | 117 |
| 05_stress_test.csv | стресс-тест: урожай и маржа каждого округа при повторе погоды 2010…2025 | 208 |

## Шаг 1. Вход и рабочая книга (5 мин)
1. Открыть datalens.ru, войти через Яндекс ID.
2. «Создать» → «Воркбук», назвать «Агромониторинг Ставрополья».

## Шаг 2. Подключение файлов (10 мин)
1. В воркбуке: «Создать» → «Подключение» → «Файлы».
2. Перетащить все пять CSV в одно подключение. Проверить, что DataLens распознал заголовки и типы:
   - «год» — целое число, «месяц» — дата;
   - всё с «_ц_га», «_руб», «_проц», «P_убытка» — дробное число;
   - «округ», «зона», «сценарий» — строка.
3. Сохранить как «agro_files».

## Шаг 3. Датасеты (10 мин)
Создать по датасету на каждый файл («Создать» → «Датасет» → источник agro_files → перетащить лист). Названия: ds_okruga, ds_urozhaj, ds_marzha, ds_ceny, ds_stress.

В ds_okruga добавить вычисляемое поле:
- `P убытка, %` = `[P_убытка_2027] * 100`

В ds_urozhaj:
- `Провал` = `IF [отклонение_проц] < -15 THEN "провал" ELSE "норма" END`

## Шаг 4. Чарты (30–40 мин)
Создавать через «Создать» → «Чарт» (Wizard).

**Экран 1 — «Пульс края»**
1. Индикатор: средняя урожайность 2025 (ds_okruga, AVG от `урожайность_2025_ц_га`).
2. Индикатор: P(убытка) по краю (AVG от `P убытка, %`).
3. Линия: цена пшеницы по месяцам (ds_ceny: X = месяц, Y = цена_пшеницы_руб_т).
4. Линия: паритет «дизель/пшеница» (ds_ceny: X = месяц, Y = паритет).
5. Столбцы: маржа края по годам (ds_marzha: X = год, Y = маржа_руб_га). Цвет по знаку: если маржа меньше 0, красный.

**Экран 2 — «Урожай и погода по округу»**
6. Линия: урожайность и тренд (ds_urozhaj: X = год, Y = урожайность_ц_га и тренд_ц_га, фильтр по округу).
7. Столбцы: отклонение от тренда, % (Y = отклонение_проц, цвет = поле `Провал`).
8. Таблица округов (ds_okruga): округ, зона, урожайность 2025, волатильность, провал 2020. Включить заливку ячеек для волатильности.

**Экран 3 — «Риск и стресс-тест»**
9. Горизонтальные столбцы: P(убытка) 2027 по округам, сортировка по убыванию (ds_okruga).
10. Таблица-матрица: строки — округ, столбцы — сценарий, значение — маржа_руб_га (ds_stress). Заливка от красного (минус) к зелёному (плюс).
11. Точечная диаграмма: X = волатильность_проц, Y = маржа_ожидаемая_руб_га, размер = площадь_пшеницы (ds_okruga) — «карта риск/доходность».

## Шаг 5. Дашборд (15 мин)
1. «Создать» → «Дашборд», три вкладки: «Пульс края», «Урожай и погода», «Риск и стресс-тест».
2. Разложить чарты; сверху каждой вкладки — текстовый виджет с выводом одной фразой (выводы берём из основной витрины).
3. Добавить селектор «округ» (на основе ds_urozhaj → поле «округ») и в настройках связей привязать его к чартам 6, 7 и 10.
4. В подвале — текстовый виджет «Источники»: БД ПМО Росстата (через tochno.st), ЕМИСС, Open-Meteo / ERA5, Росстат (цены), direct.farm (техкарта).

## Шаг 6. Публичная ссылка (5 мин)
1. В дашборде: «Поделиться» → включить публичный доступ (DataLens предупредит, что данные станут видны всем — у нас только открытые данные, это нормально).
2. Открыть ссылку в режиме инкогнито и убедиться, что всё видно без входа.
3. Ссылку вставить в форму конкурса вторым пунктом: «Резервная версия в Yandex DataLens».

## Что сказать, если спросят «почему два дашборда»
Основная витрина — своя веб-страница: в ней работают расчёты (Монте-Карло, стресс-тест, живая погода), которые BI-инструмент делать не умеет. DataLens показывает, что те же данные без доработки ложатся в стандартный корпоративный BI, то есть решение можно встроить в инфраструктуру банка.
